# Pathleap / 跃径

Windows 桌面快速定位工具：全局热键唤出、输入即搜、结果列表键盘直达。
UI 是常驻托盘进程，索引与查询放在独立的长驻服务进程，两者只通过命名管道通信。

> 没验证的写「未验证」，不把计划中的发布写成已达成。数字出处见每节引用与 [文档索引](#9-文档索引)。

## 1. 产品定位与当前状态

**定位**：面向 Windows 10/11 x64 的轻量快速定位工具。目标是在按下热键后几十毫秒内可输入，
并在本地索引上以低延迟返回文件名匹配结果。

**设计取舍**：

- UI 只负责窗口、热键、列表与键盘交互；索引构建、装载与查询全部在服务进程，避免大索引拖慢 UI 线程。
- 索引是单个只读 mmap 文件，查询零拷贝；构建放到短生命周期子进程，构建期的 GB 级临时内存不留在常驻服务里。
- 优先走 USN/MFT 主路径；拿不到卷句柄时降级目录遍历，保证功能可用。
- 更新只读**公开主仓库**（`yunyu697/pathleap`）最新 Release 的签名清单（无令牌）；tag 触发 CI
  构建 zip 与安装包，并连同 `latest.json`、`latest.json.sig` 一起发布到该 tag 的 Release。

### 未完成项（明确不做已完成表述）

- **`1.0.1`–`1.0.3` 的 Release 只有 zip 与安装包**：这几个 Release 早于清单机制，没有 `latest.json`，
  因此清单地址在 1.0.4 发布前仍会 404；1.0.4 的清单由本地生成后补传到同一 Release，
  `1.0.5` 起由 tag 流水线自动生成并上传清单与分离签名。
- **清单缺失或网络失败只报错不猜测**：手动检查在窗内红字显示原因，自动检查写 WARN 日志并托盘提示
  「更新检查未完成」（见下方「托盘提示的验证口径」），不会谎报有更新。
- **自动检查更新的失败只在托盘提示一次**：窗口内没有「上次检查结果」的历史记录，需要用户点「检查更新」才能看到完整原因。
- **1.0.0–1.0.4 的客户端没有签名校验**：它们走 `api.github.com/releases/latest`，能发现新版本
  （实测 1.0.4 发现 1.0.5、`update=True`），但不验签、不校验 SHA256；首个验签版本是 `1.0.5`，
  旧版本用户应手动升级，不要依赖旧客户端的无校验下载。
- **运行期自动刷新只在 USN 索引上生效，且是「变更检测 + 整重建」，不是逐条增量**：`FSCTL_READ_USN_JOURNAL`
  只用来检测「有变更、变了多少」，安静 60 秒后自动重建（最小间隔 15 分钟）；目录遍历模式或拿不到卷句柄（非管理员）时仍需手动「重建索引」。
  逐条增量的可行性与数据见 §2.3「运行期自动刷新」。
- **只维护一个活跃索引文件**（单卷）；多卷合并未实现。
- **没有 SCM 服务安装**：服务由 UI 以同目录子进程拉起（`--console`），未注册为 Windows 服务。
- **预发布版本不会出现在 `/releases/latest`**：GitHub 的 `latest` 只指向最新非预发布 Release；`alpha` 通道未实现。
- **更新镜像只有 GitHub 直链一种**：没有自建源就不提供可选镜像；资产不是 `github.com` 直链时
  更新窗明确显示「镜像不可用」，不保留点了没效果的选项。
- **1.0.7 的界面收口：缩放四档已全档实拍（2026-11-13）**：100%/125%/150%/200% 下设置窗
  标题栏按钮逐像素量测全部符合 12×12 DIP 设计几何（见 [1.0.7-发布说明](docs/1.0.7-发布说明.md) §3.1、
  [界面验收报告](docs/界面验收报告.md) §2.4）；负坐标副屏上的光标屏居中已实拍（零偏差，§2.5、shots 43）；
  主窗失焦即隐藏，任务栏没有独立按钮可截，
  图标身份以托盘实拍与 ICO 导出为准。详见 [1.0.7-发布说明](docs/1.0.7-发布说明.md) §10。
- **文件对话框注入只覆盖标准对话框**：系统 `#32770` 的「打开 / 另存为 / 选择文件夹」（含资源管理器与 WinForms）已接入；
  自绘选择器（浏览器上传、部分 Electron 应用）不识别，浮层会如实显示「未检测到文件对话框」并退回资源管理器打开。
- **设置页只有四页**：外观与主题、快捷键、搜索范围与索引、更新；设计稿侧栏的「常规」「关于」未做，界面上标注「未接入」。
- **窗口圆角跟随 Windows 11 系统圆角（约 8 DIP）**：设计稿为 14 DIP；WinUI 3 无自定义窗口圆角 API，强行区域裁剪会丢阴影与抗锯齿，故保留并在验收报告中列为已知差异。
- **前台唤醒基准的 alpha5 重试修复仍未取得有效前台数据**（采集时会话锁屏）；`Enter` 打开真实目标已在 2026-11-08 用真实对话框与真实按键验收（见 [quick-switch-attach.md](docs/quick-switch-attach.md)「`Enter` 真实链路验收」）。

## 2. 安装与运行

### 2.1 两种分发形式

tag 触发时由 CI 构建并上传到该 tag 的 Release；本机同样可以用两条 `Package-*` 脚本产出等价产物，放在 `dist/`。
仓库与 Release 均为公开（源码主仓库即更新源），客户端读取清单不需要任何令牌。

| 产物 | 形式 | 适用场景 | 与另一种的差异 |
| --- | --- | --- | --- |
| `Pathleap-<版本>-win-x64.zip` | 便携版 | 解压即用、绿色部署、放到 U 盘或受控目录 | 不写注册表、不建快捷方式、不产生卸载项；升级/删除需手动覆盖或删目录 |
| `Pathleap-<版本>-win-x64-setup.exe` | 安装包（Inno Setup） | 需要快捷方式/卸载项的用户 | 安装范围二选一（见下表）；可选择安装目录；创建开始菜单快捷方式，桌面快捷方式为可选任务；按范围写入用户级或机器级卸载项 |

安装包在向导第一步显式选择安装范围，**默认「仅为我安装」**（推荐），也可以选「为所有用户安装」：

| 项 | 仅当前用户（默认） | 为所有用户安装 |
| --- | --- | --- |
| 安装目录 | `%LOCALAPPDATA%\Programs\Pathleap`（可改） | `C:\Program Files\Pathleap`（可改） |
| 权限 | 不需要 UAC | 需要管理员权限，安装前弹 UAC |
| 开始菜单 | 当前用户开始菜单 | 公共开始菜单（All Users） |
| 卸载项 | `HKCU\...\Uninstall` | `HKLM\...\Uninstall` |
| 数据 / 日志 / 索引 | `%LOCALAPPDATA%\Pathleap`（当前用户） | 仍然按用户隔离，各用户各自一份 |
| 开机自启 | 无（当前版本没有自启功能，不写 Run 项） | 无（同上，不写机器级 Run 项） |
| 服务 | 由 UI 拉起同目录子进程 | 同左，**不注册 SCM 服务** |

默认值取「仅当前用户」的理由：不需要提权，也不会把程序写进机器级目录，降低误装与被替换的风险；只有多人共用同一台机器时才需要「所有用户」。
数据不跟随安装范围：索引反映每个用户自己可见的文件，机器级共用会泄露他人的文件列表，所以两种模式的数据、日志、索引都按用户隔离。
安装范围写入 `HKLM\Software\Pathleap` 或 `HKCU\Software\Pathleap` 的 `InstallScope` 值（64 位视图），设置界面据此显示当前模式。
实现见 [Pathleap.iss](installer/Pathleap.iss)（`PrivilegesRequired=lowest` + `dialog commandline`）。

安装完成可选择立即启动 UI（以原用户身份启动，不继承安装时的提权）；UI 会按配置 `startServiceWithUi` 自动拉起同目录的
`Pathleap.Service.exe --console`，不需要单独启动服务。

**静默安装/卸载**：`Pathleap-<版本>-win-x64-setup.exe /VERYSILENT /ALLUSERS` 或 `/CURRENTUSER`；卸载用安装目录下的
`unins000.exe /VERYSILENT`。所有用户模式的卸载需要提权。

**卸载与用户数据取舍**：

- 程序文件、开始菜单/桌面快捷方式、卸载注册项一律清除；安装范围注册值一并删除。
- 配置、日志、索引缓存（`%LOCALAPPDATA%\Pathleap`）**默认保留**：升级或重装后可以直接沿用索引与配置。
- 交互式卸载会询问「是否同时删除当前用户的配置、日志与索引缓存」；选「是」才删除该目录。静默卸载默认保留。
- 「所有用户」模式只删除**执行卸载的这位用户**的数据，其他用户的数据保留。
- 需要彻底清理时，请先退出 Pathleap，再删除各用户的 `%LOCALAPPDATA%\Pathleap` 即可。

### 2.2 运行前提

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 系统 | Windows 10/11 x64 | 安装包声明 `x64compatible` |
| .NET | .NET 8 Desktop Runtime | 当前产物是框架依赖构建，未自带运行时 |
| Windows App SDK | Windows App Runtime 2.6.5 | UI 是 unpackaged WinUI 3 应用 |
| 管理员 | **运行非必需**；仅「所有用户」安装需要 | 非管理员可正常搜索；USN 主路径需要管理员或 LocalSystem，非管理员 `auto` 会降级目录遍历 |

### 2.3 首次使用：启动后自动建索引

服务启动即自检索引文件，**不存在或构建时间超过 7 天**就在后台自动开始构建，不需要用户操作，
也不阻塞 UI 连接管道。索引文件落在 `%LOCALAPPDATA%\Pathleap\service\index\<卷>.plidx`。

- **进度可见**：主窗空态与底栏显示「索引构建中 · 已扫描 N 条」，设置页同步显示阶段、条目数与警告；UI 每秒轮询服务状态。
- **构建期间可搜**：重建时保留上一次索引，查询继续可用，结果页与底栏注明「结果来自上一次索引（N 条）」；
  首次构建尚无旧索引时，搜索会明确返回「索引构建中：…，完成后自动可搜」。
- **降级不静默**：非管理员拿不到卷句柄时自动降级为目录遍历，状态带警告「USN 主路径不可用：…；已降级为目录遍历」，底栏显示「降级模式」。
- **失败不静默**：构建失败且旧索引可装载时保持可用，并给出「上次索引仍可用（N 条）；本次构建失败：原因」；
  没有可用旧索引时置为错误态，设置页显示失败原因。
- **手动重建**：设置 → 搜索范围与索引 →「重建索引」，请求立即回执，进度与自动构建一致。
- **运行期自动刷新（USN 索引）**：服务保持卷句柄，用 `FSCTL_READ_USN_JOURNAL` 检测运行期的文件变化；
  连续写入安静 60 秒后自动重建，且两次自动重建至少间隔 15 分钟，避免安装/编译把索引反复重扫。
  目录遍历索引、或非管理员拿不到卷句柄时不启用，日志明确写明原因，仍需手动重建。

**逐条增量评估（2026-11-08，结论：暂不做，保留整重建）**：

- **没有数据源**：便携/非管理员模式下 `CreateFileW(\\.\C:)` 被拒，`--usn-watch-probe` 实测
  `start=false error=打开卷句柄被拒绝（ERROR_ACCESS_DENIED，Win32 5）`（退出码 5），构建降级为 `walk:C:`；
  该模式下拿不到任何 USN 记录，增量的前提不存在。
- **格式缺 FRN**：索引格式 v4 每条只有「父索引、名称、标志」，不存 `FileReferenceNumber`。USN 给的是
  `FileReferenceNumber / ParentFileReferenceNumber`，要还原完整路径必须先建 FRN→路径表；按 1,187,745 条
  （目录 177,166 / 文件 1,010,579）估算，文件级映射必须把全部名称反序列化进内存，
  正好抵消 mmap 的零解析优势（装载实测 2–3 ms）。
- **整重建代价可接受**：`--build-once walk C:\` 实测 1,206,930 条 / 36.9 MB，暖缓存 23.6 s（扫描 23.57 s + 写盘 1.76 s）、
  冷缓存 51.9 s；扫描阶段旧索引照常可搜，只有写盘 1.76 s 不可搜。本机 21.7 小时新增 19,185 条（约 882 条/小时），
  按 15 分钟最小间隔触发，重建占空比约 2.6%–5.8% 单核。
- **结论**：真正的逐条增量需要（a）管理员/服务身份，（b）索引格式升版并持久化 FRN（目录与文件两级映射），
  且必须在该权限下补实测；在没有 USN 的便携模式无法验证，故不引入无法实测的补丁逻辑。

实测（本机 200% 缩放，C: 目录遍历）：清空索引后冷启动，启动 2 秒内自动开始；1,187,262 条约 58 秒完成，
索引 34.5 MB；完成后查询 `explorer` 24 条、0.3 ms；索引未过期时重启直接 `ready` 并跳过构建。
来源：[1.0.4-发布说明](docs/1.0.4-发布说明.md) §2。

需要单独为某个目录建索引时仍可用基准脚本（会覆盖同卷 `.plidx`，先备份）：

```powershell
pwsh -File .\tools\Run-LpIndexBench.ps1 -LpBuild -LpMode walk -LpRoot 'C:\Windows' -LpIterations 1
```

### 2.4 热键：默认双击 Ctrl 与其它预置

默认唤醒方式是**连续两次 `Ctrl`**：判定窗口 380 ms，长按阈值 400 ms；期间出现其它按键（如 `Ctrl+C`）立即作废，
不吞 `Ctrl+C/V`、`Ctrl+拖动` 与 `Ctrl+点击多选`。实现走低层键盘钩子（`WH_KEYBOARD_LL`），左右 `Ctrl` 统一归一。

设置 → 快捷键提供 6 种预置，选中即生效并写入 `config.json` 的 `uiHotkey`：

| 预置 | 实现方式 | 备注 |
| --- | --- | --- |
| 双击 Ctrl（默认） | 低层键盘钩子，间隔 ≤380 ms | 长按不触发 |
| 双击 Alt | 同上 | 部分应用里单按 Alt 会激活菜单栏 |
| 双击 Shift | 同上 | 与输入法连续 Shift 切换易误触 |
| Ctrl + Alt + Space | `RegisterHotKey` | 可能与输入法/其它软件冲突 |
| Ctrl + Shift + Space | `RegisterHotKey` | 冲突面较小，部分输入法占用 |
| Ctrl + Alt + F | `RegisterHotKey` | 注意与编辑器/游戏快捷键冲突 |

钩子被安全软件拦截时，状态行与托盘会提示；原生消息线程每 15 秒自检并重装钩子，防系统静默摘钩。
鼠标中键/侧键需要额外的鼠标钩子，**本版未接入**，界面如实标注。
来源：[1.0.4-发布说明](docs/1.0.4-发布说明.md) §3、[HotkeySpec.cs](src/Pathleap.UI/Platform/HotkeySpec.cs)。

搜索窗失焦自动隐藏，`Esc` 隐藏并清空查询，`Enter` 打开选中项（目录用资源管理器、文件用系统默认程序）。

### 2.5 始终以管理员身份运行

设置 → 更新 →「安装与权限」卡片里可以开启「始终以管理员身份运行」，也可以查看当前安装模式
（仅当前用户 / 所有用户 / 便携版）、维护者与安装目录。安装范围切换需要重新运行安装包，卡片里已写明。

实现方式：开关打开时注册一个**无触发器的计划任务**（`Pathleap-Elevated-<用户SID>`，`RunLevel=HighestAvailable`），
之后每次启动由未提权的启动器写交接文件、用 `schtasks /Run` 拉起该任务，再以 `--elevated-launch` 恢复原参数。
**不使用 `HKCU\...\Run` 注册表项**，因此不会出现「登录后静默提权」的行为。注册/取消任务各需要一次 UAC。

代价与限制（界面中同步提示，不能隐去）：

- **UIPI**：提权后的窗口完整性级别更高，资源管理器（未提权）无法把文件/文件夹拖进提权窗口；需要拖放时请关闭该开关。
  这是 Windows 的跨完整性级别限制，不是 Pathleap 自身的 bug。
- 计划任务按用户隔离；同一台机器上的其他用户需要各自开启。
- 便携版同样可用，但由于没有安装范围注册值，设置卡片会显示「便携版」。

已验证：开启后 `--tray` 由计划任务拉起（`elevated=True`），`--status` 与 `--quit` 经命名管道转发成功，
删除任务后回到普通权限且功能正常；详见 [1.0.2-发布说明](docs/1.0.2-发布说明.md) §3。**未验证**：在设置界面用鼠标点击开关完成
「注册任务 → 重启提权」的完整链路（该控件没有可自动化的 UIA Invoke），以及提权后资源管理器拖放的实拍。

### 2.6 快速切换：吸附栏、Ctrl+G 浮层与对话框注入

**吸附栏（文件对话框打开时）**：以 owner 窗口贴在文件对话框底边**外侧** 2px，宽度取对话框可视宽度的一半并水平居中，
`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`，显示与点击都不抢焦点。生命周期完全跟随对话框：

- `SetWindowLongPtr(栏, GWLP_HWNDPARENT, 对话框)` 建 owner（**不是 `SetParent`**，避免压住对话框底部的「文件名 + 打开/取消」按钮行）；
- `SetWinEventHook`（`WINEVENT_OUTOFCONTEXT`）监听创建/显示/隐藏/销毁、位置变化、前台切换、最小化/还原，据此挂载、随动、销毁；
- 多对话框各一条栏，`GetWindowLongPtr(-8)` 可逐条核对归属，不串位；只显示前台对话框那条，
  后台栏隐藏（避免互叠时压住后方内容），键盘也只路由给前台那一条；后台对话框被最小化/还原（不激活）
  不会把栏重新带出来（`AppWindow.Changed` 的可见性事件兜底）；
- 栏按**对话框所在显示器**的 DPI 与工作区计算：跨屏拖动时每次位置变化都重算缩放、半宽、间距与列数，
  不沿用上一屏坐标；对话框横跨两屏时只贴在被选屏（约等于所占面积更大那块）的内侧；
- 对话框关闭立即销毁对应栏（进程被强杀同样立即移除，无残留）；最小化时随系统隐藏，还原后贴回底边；
- 已知限制：对话框最大化时栏回退到工作区顶部附近（只覆盖标题栏）；栏宽 <360 DIP 时内容退到 **2 列**
  （6 个文件夹排 3 行、单格文字约翻倍），超长名仍省略，悬停 tooltip 显示完整路径。

实测（2026-11-07，200% 缩放）：初始挂载对话框 1440×960、栏 706×220（宽比 0.49、间距 2px、居中偏差 0）；
拖动 +220,+90 后栏位移完全一致；缩放对话框时栏实时重排为 3 列；两个对话框 owner 各自独立；关闭一个只销毁对应栏。
2026-11-08 复测边界：两个对话框重叠时后台栏 `IsWindowVisible=False`、前台为 True；最大化时栏回退到工作区顶部（1424×156，6 列）；
强杀对话框进程后该栏立即移除（total=0）。
同日核对多显示器（本机单屏，离屏探针合成三屏：左 150% / 主 125% / 右 100%）：同一 720×480 DIP 对话框
在三屏上的栏分别为 540×165 / 450×138 / 360×110，间距 3/2/2px，均落在各自工作区内；跨屏拖动栏宽 360→450→540px、

## 3. 索引与搜索的工作方式

### 3.1 索引来源：USN 主路径 + 降级

1. `mode=usn`：打开卷句柄 `\\.\C:` 的 `GENERIC_READ`，用 `FSCTL_ENUM_USN_DATA` 枚举 MFT 记录，直接得到
   文件名、父引用、大小与时间。**需要管理员或 LocalSystem**；非管理员会得到 Win32 错误 5。
2. `mode=auto`：优先 USN；拿不到卷句柄或 USN 失败时自动降级为目录遍历（`walk`），日志留痕，
   并把降级原因作为警告写入索引状态，界面底栏显示「降级模式」、设置页显示原因（自动建索引默认走 `auto`）。
3. `mode=walk` / 非卷路径：从指定根目录递归枚举，适合只索引某个目录或没有管理员权限时使用。

USN 实测（管理员，整卷 `C:\`）：1,110,379 条、构建 10,822 ms、索引 32.70 MB（30.88 B/条），
来源标记 `usn:\\.\C:` 证明走的是主路径而不是降级。来源：[1.0.0-发布说明](docs/1.0.0-发布说明.md) §1.3。

### 3.2 索引文件格式（v4）

```
[Header 256B][Record 16B × N][PrefixLens 1B × N][名字后缀区]
```

- 记录 16 字节：`NameOffset u32 / ParentIndex i32 / SizeAndFlags u32 / LengthDepth u16 / ModifiedDays u16`。
- 名字按「折叠小写」排序；每 5 条一组做公共前缀编码，组首存全名，其余只存前缀之后的字节。
- 读取侧 `MemoryMappedFile` + `AcquirePointer`，查询零拷贝；不反序列化整表。
- 体积实测：`C:\` 全卷 30.88 B/条；`C:\Windows` 43.68 B/条；`C:\Windows\WinSxS` 48.72 B/条；
  5M 合成 25.46 B/条。按真实名字分布外推 5M 约 154 MB。来源：[M2-索引与搜索报告](docs/M2-索引与搜索报告.md) §10.2。

实现：`src/Pathleap.Shared/Index/IndexSnapshot.cs`（格式与装载）、`IndexBuilder.cs`（构建）、`DirectoryIndexSource.cs`（遍历源）。

### 3.3 查询

- T0 完全相等（tier 100）、T1 前缀（85）、T2 子串（70）；多 token 按 AND 组合。
- 前缀用二分（`LowerBound` / `UpperBoundOfPrefix`）；子串用 `SearchValues<byte>` + 分片并行扫描。
- 结果直接按 `(tier, 深度)` 分桶，不做全量排序；前缀命中已够填满结果集时跳过整段子串扫描。
- junction 命中按前缀块成组遍历，先用后缀首字节快速否决。

实现入口：[SearchEngine.cs](src/Pathleap.Shared/Index/SearchEngine.cs)、[IndexSnapshot.cs](src/Pathleap.Shared/Index/IndexSnapshot.cs)。

| `Pathleap.Service.exe` | 命名管道控制面（`PING/STATUS/SEARCH/INDEX_STATUS/INDEX_BUILD`）、索引装载、构建与查询 | 由 UI 拉起（`--console`），UI 退出时一并结束；也可手动以控制台/SCM 模式运行 |

服务 IPC 只绑定命名管道，不监听网络端口。索引构建通过 `Pathleap.Service.exe --build-once <mode> <root> <output>`
短生命周期子进程执行，父进程只读取 `.result.json` 摘要。
`Pathleap.ReleaseTool` 不随发行包分发（`IsPublishable=false`），只在源码仓库与 CI 中使用。

## 6. 构建、打包与 CI

```powershell
# 编译（先跑脚本变量命名检查，并把服务产物复制进 UI 输出目录）
pwsh -File .\tools\Build-Lp.ps1 -LpConfiguration Release

# 便携 zip：dist\Pathleap-<版本>-win-x64.zip
pwsh -File .\tools\Package-Lp.ps1

# 安装包：dist\Pathleap-<版本>-win-x64-setup.exe（需要 Inno Setup 6）
pwsh -File .\tools\Package-LpInstaller.ps1

# 发布工具：自检 / 生成签名清单 / 验签
dotnet run --project src/Pathleap.ReleaseTool -- selftest
dotnet run --project src/Pathleap.ReleaseTool -- create --version 1.0.4 --tag v1.0.4 `
  --notes-file docs/1.0.4-发布说明.md `
  --installer dist/Pathleap-1.0.4-win-x64-setup.exe `
  --portable dist/Pathleap-1.0.4-win-x64.zip `
  --out dist/latest.json --seed-file release-keys/ed25519-seed.txt
dotnet run --project src/Pathleap.ReleaseTool -- verify --manifest dist/latest.json
```

本机安装包编译可用 Inno Setup 6；脚本会依次查找 PATH、
`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`、`%ProgramFiles%\Inno Setup 6\ISCC.exe`。

CI（[build.yml](.github/workflows/build.yml)）按触发条件区分：

- **main / PR**：解析版本号（校验格式）→ 脚本变量命名检查 → 发布工具 `selftest` → Release 编译，不产包、不发布。
- **tag `v*`**：在上面的基础上，用 tag 版本注入编译，打包 zip 与安装包 → 核对 zip 必须包含
  `runtimes\win-x64\native\Microsoft.WindowsAppRuntime.Bootstrap.dll` → 创建/更新该 tag 的 Release 并上传
  `Pathleap-<版本>-win-x64.zip`、`Pathleap-<版本>-win-x64-setup.exe`；配置了 secret `PATHLEAP_SIGNING_KEY` 时
  再生成并上传 `latest.json` 与 `latest.json.sig`（缺少 secret 会在日志与注解中告警，且不生成、不上传未签名清单）。

本机仍可用上面两条 `Package-*` 脚本产出等价产物（备用路径），清单用 `ReleaseTool create` 本地签名。

## 7. 更新检查与签名清单

- 客户端只请求公开主仓库最新 Release 的 `latest.json`：
  `https://github.com/yunyu697/pathleap/releases/latest/download/latest.json`，**不携带任何令牌**，
  没有第二套私有源逻辑。
- **清单缺失时的表现（2026-11-08 实测）**：`1.0.1`–`1.0.3` 的 Release 只有 zip 与安装包，该地址真实返回 HTTP 404；
  客户端据此返回「主仓库暂无最新清单（HTTP 404）：<清单地址>」，手动检查在窗内以红字显示
  「检查失败：主仓库暂无最新清单（HTTP 404）…」；自动检查写 WARN 日志并以托盘提示「更新检查未完成」告知
  （见「托盘提示的验证口径」），绝不显示「有新版本」。
- **托盘提示的验证口径（2026-11-08 实测）**：把清单地址临时指向不可达地址 `https://127.0.0.1:9/…`，
  启动 `--tray` 后日志按顺序出现
  `[WARN] 更新检查失败: … (127.0.0.1:9)` → `[WARN] 自动检查更新未完成: …` →
  `[INFO] 托盘提示已提交: title="更新检查未完成" warning=False ok=True`。
  `ok=True` 是 `Shell_NotifyIconW(NIM_MODIFY, NIF_INFO)` 的真实返回值，说明气泡已被系统接受；
  当时会话处于锁屏（`LockApp`/`LogonUI` 在运行、`GetForegroundWindow()==0`），全屏截图只能拍到黑屏，
  因此**气泡外观的截图证据仍缺**，只以系统返回值与日志为证。
- 清单字段：`schemaVersion`、`version`、`tag`、`releasedAt`、`channel`、`platform`（`win-x64`）、
  `minimumSystem`（Windows / .NET Desktop / Windows App Runtime）、`assets`（文件名、大小、SHA256、URL）、`notes`、`signature`。
- 验签：Ed25519（RFC 8032，托管实现），公钥内置在客户端；签名覆盖固定文本（含 URL 与 SHA256），
  签名失败**直接中止**，不提供「忽略签名继续安装」开关。
- 下载：先写 `.part`，边下边算 SHA256；大小或哈希不符就删除临时文件并拒绝安装，提示期望值与实际值。
- 下载源：资产是 `github.com` 直链时显示「GitHub 官方直链」，否则显示「资产不是 github.com 直链（host），镜像不可用」，
  不保留死选项。
- **私钥固定**：本项目固定使用 `release-keys/ed25519-seed.txt` 这一把私钥，发布流程**不得生成新钥**；
  `create` 若发现 seed 公钥与内置公钥不一致会直接失败、不产出清单。换钥必须先发布内置新公钥的客户端，
  再用新钥签清单（本机 `dist/latest.json`）。
- **老版本兼容**：`1.0.0`–`1.0.4` 客户端走 GitHub Releases API，能发现新版本但不验签、不校验 SHA256
  （实测 1.0.4 发现 1.0.5、`update=True`）；首个带签名校验的版本是 `1.0.5`，旧版本用户应手动升级。

## 8. 版本号规则

版本号唯一来源是 [Directory.Build.props](Directory.Build.props) 的 `PathleapVersion`；程序集版本、程序内显示、
zip/安装包名、编译时注入版本都由它派生。规则摘要：

- 格式 `<major>.<minor>.<patch>[-alpha<N>]`；`major` 不设上限，`minor` / `patch` 取 0–10，超过 10 向前进位。
- 预发布用 `alphaN`；正式版落到数字版本（当前 `1.0.5`）。
- tag 带 `v` 前缀（`v1.0.5`）：CI 校验 tag 格式、注入版本编译、打包 zip 与安装包，并发布到该 tag 的 Release。
  升级用 `pwsh -File .\tools\Next-LpVersion.ps1 -LpBump patch -LpApply`。
- 完整进位示例与「下一版是什么」见 [版本号规则](docs/版本号规则.md)。

## 10. 已知限制与未完成项

1. **旧 Release 没有清单**：`1.0.1`–`1.0.3` 只上传了 zip 与安装包；`1.0.4` 的清单是本地补传，`1.0.5` 起由 tag 流水线自动生成。
2. **清单缺失或网络失败时更新检查报错**：客户端显示「主仓库暂无最新清单（HTTP 404）」等原始原因，
   并在自动检查时给出托盘提示；这是如实失败，不是静默，也不是「有新版本」。
3. **旧版本需手动升级**：`1.0.0`–`1.0.4` 走 GitHub Releases API，能发现新版本但不验签、不校验 SHA256；首个带签名校验的版本是 `1.0.5`。
4. **运行期自动刷新依赖 USN 与管理员**：USN 索引会在检测到变更、安静 60 秒后自动重建（最小间隔 15 分钟）；
   目录遍历索引（非管理员）不自动刷新，仍需手动「重建索引」。首次构建完成前进度可见，但没有旧索引时搜索只能返回「索引构建中」提示。
5. **索引是单卷/单文件**：`LoadLatest` 只装载最新的一个 `.plidx`，多卷合并未实现。
6. **自动刷新是重建而非逐条增量（已评估，2026-11-08）**：USN 记录只用于「有变更」检测，随后整重建。
   逐条增量需要管理员/服务身份与带 FRN 的索引格式；现有整重建暖 23.6 s / 冷 51.9 s、写盘黑屏 1.76 s，
   本机约 882 条/小时变更，成本可接受，故暂不做，数据与理由见 §2.3「逐条增量评估」。
7. **无 SCM 服务安装**：服务随 UI 启动；不随系统开机常驻。
8. **预发布通道未实现**：`/releases/latest` 只指向最新非预发布 Release。
9. **文件对话框注入仅覆盖标准对话框**：浏览器上传、Electron 自绘选择器等不识别，浮层会提示「未检测到文件对话框」并退回资源管理器打开。
10. **窗口圆角为系统值（约 8 DIP）**：与设计稿 14 DIP 存在差异，权衡理由见 [界面验收报告](docs/界面验收报告.md)。
11. **前台唤醒基准待复测**：alpha5 重试修复没有有效前台样本，现有最新前台数据仍是 M1 的 1000 次结果。
12. **`Enter` 打开目标已完成前台验收（2026-11-08）**：快速切换栏在真实文件夹对话框中注入并进入目标目录（44 ms 注入、272 ms 可见），
    主窗 `Enter` 拉起资源管理器并前台化（749–783 ms，`LocationURL` 与选中项一致）；细节见 [quick-switch-attach.md](docs/quick-switch-attach.md)。
    早期 2 次未注入的现象未复现，5 次复测（含正式构建）全部通过。
13. **真实整卷索引在本地测试中会被覆盖**：基准脚本会把 5M 合成索引写到同一路径；需要真实卷数据时重新跑 USN 构建。
14. **多显示器只有离屏数值验收**：本机单屏（200%），跨屏拖动用 `--layout-probe` 的合成三屏（左 150% / 主 125% / 右 100%）
    核对缩放、半宽、间距、列数、工作区夹紧与逐步重算；两块不同 DPI 的真实显示器间的 `WM_DPICHANGED` 重排未实测。
15. **125% / 150% 已真机截图，其它档位仍为数值验收**：2026-11-08 真实切缩放并用真实对话框截图（见 §2 与
    [quick-switch-attach.md](docs/quick-switch-attach.md)「真机 125% / 150% 肉眼验收」）；100% / 175% / 225% 没有截图；
    切缩放后系统 DPI 感知的旧对话框可能需要重启宿主进程才按新比例绘制。

## 脚本安全约定

- 所有 PowerShell 自定义变量以 `Lp` 开头；`tools/Test-LpVariableNames.ps1` 用 AST 检查，`Build-Lp.ps1` 会先执行。
- 删除/清理只走 `tools/Lp.Safety.psm1` 的 `Remove-LpItemSafely`：路径白名单、`-WhatIf`、删除前打印绝对路径。
- 测试默认后台/离屏（UI `--tray`、服务 `--console`）；前台唤醒基准必须显式 `-LpAllowForeground`，并且每轮集中跑一次。
