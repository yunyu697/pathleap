# Pathleap / 跃径

Windows 桌面快速定位工具：全局热键唤出、输入即搜、结果列表键盘直达。
UI 是常驻托盘进程，索引与查询放在独立的长驻服务进程，两者只通过命名管道通信。

> 当前版本：`1.0.4`（2026-11-07）。本 README 描述的是**已经实测验证**的状态，
> 未验证的能力统一放在「已知限制与未完成项」，不会写成已达成。数据来源见每节末尾与
> [文档索引](#8-文档索引)。

## 1. 产品定位与当前状态

**定位**：面向 Windows 10/11 x64 的轻量快速定位工具。目标是在按下热键后几十毫秒内可输入，
并在本地索引上以低延迟返回文件名匹配结果。

**设计取舍**：

- UI 只负责窗口、热键、列表与键盘交互；索引构建、装载与查询全部在服务进程，避免大索引拖慢 UI 线程。
- 索引是单个只读 mmap 文件，查询零拷贝；构建放到短生命周期子进程，构建期的 GB 级临时内存不留在常驻服务里。
- 优先走 USN/MFT 主路径；拿不到卷句柄时降级目录遍历，保证功能可用。

### 未完成项（明确不做已完成表述）

- **自动建索引只在服务启动时判定一次**：缺失或构建超过 7 天才重建；运行期间的文件增删改不会自动触发重建，需要设置页手动「重建索引」。
- **没有 USN 增量更新**：只实现了 USN 全量枚举；`FSCTL_READ_USN_JOURNAL` 的持续增量未接入。
- **只维护一个活跃索引文件**（单卷）；多卷合并未实现。
- **没有 SCM 服务安装**：服务由 UI 以同目录子进程拉起（`--console`），未注册为 Windows 服务。
- **公开发布仓库流水线尚未在真实 CI 跑通**：账户计费阻断，本轮只做了本地 dry-run（生成清单、验签、篡改拒绝）；
  `PATHLEAP_RELEASES_PAT` 与 `PATHLEAP_SIGNING_KEY` 到位后需重跑 tag 验证。
- **预发布版本不会出现在 `/releases/latest`**：GitHub 的 `latest` 只指向最新非预发布 Release；
  `alpha` 版本需要单独测试通道（未实现）。
- **更新镜像只有 GitHub 直链一种**：没有自建源就不提供可选镜像；资产不是 `github.com` 直链时
  更新窗明确显示「镜像不可用」，不保留点了没效果的选项。
- **文件对话框注入只覆盖标准对话框**：已支持系统 `#32770` 的「打开 / 另存为 / 选择文件夹」（含资源管理器与 WinForms）。自绘选择器（如浏览器内上传、部分 Electron 应用）不识别，浮层会如实显示「未检测到文件对话框」并退回资源管理器打开。
- **设置页只有四页**：外观与主题、快捷键、搜索范围与索引、更新；设计稿侧栏的「常规」「关于」未做，界面上以「未接入」标注相关项，不放假控件。
- **窗口圆角跟随 Windows 11 系统圆角（约 8 DIP）**：设计稿为 14 DIP；WinUI 3 无自定义窗口圆角 API，强行区域裁剪会丢阴影与抗锯齿，故保留系统圆角并在验收报告中列为已知差异。
- **前台唤醒基准的 alpha5 重试修复未取得有效前台数据**（采集时会话锁屏）；`Enter` 打开真实目标的最后一步也未前台验收。

## 2. 安装与运行

### 2.1 两种分发形式

公开发布仓库 [`yunyu697/pathleap-releases`](https://github.com/yunyu697/pathleap-releases) 的 Release 同时提供
（源码仓库保持私有，公开仓库只放产物与签名清单）：

| 产物 | 形式 | 适用场景 | 与另一种的差异 |
| --- | --- | --- | --- |
| `Pathleap-<版本>-win-x64.zip` | 便携版 | 解压即用、绿色部署、放到 U 盘或受控目录 | 不写注册表、不建快捷方式、不产生卸载项；升级/删除需手动覆盖或删目录 |
| `Pathleap-<版本>-win-x64-setup.exe` | 安装包（Inno Setup） | 需要快捷方式/卸载项的用户 | 安装范围二选一（见下表）；可选择安装目录；创建开始菜单快捷方式，桌面快捷方式为可选任务；按范围写入用户级或机器级卸载项 |

安装包在向导第一步显式选择安装范围，**默认「仅为我安装」**（推荐），也可以选「为所有用户安装」：

| 项 | 仅当前用户（默认） | 为所有用户安装 |
| --- | --- | --- |
| 安装目录 | `%LOCALAPPDATA%\Programs\Pathleap`（可改） | `C:\Program Files\Pathleap`（可改） |
| 权限 | 不需要 UAC | 需要管理员权限，安装前弹 UAC |
| 开始菜单 | 当前用户开始菜单 | 公共开始菜单（All Users） |
| 卸载项 | `HKCU\...\Uninstall` | `HKLM\...\Uninstall` |
| 数据 / 日志 / 索引 | `%LOCALAPPDATA%\Pathleap`（当前用户） | 仍然按用户隔离，各用户各自一份 |
| 开机自启 | 无（当前版本没有自启功能，不写 Run 项） | 无（同上，不写机器级 Run 项） |
| 服务 | 由 UI 拉起同目录子进程 | 同左，**不注册 SCM 服务** |

默认值取「仅当前用户」的理由：不需要提权，也不会把程序写进机器级目录，降低误装与被替换的风险；只有多人共用同一台机器时才需要「所有用户」。
数据不跟随安装范围：索引反映每个用户自己可见的文件，机器级共用会泄露他人的文件列表，所以两种模式的数据、日志、索引都按用户隔离。
安装范围写入 `HKLM\Software\Pathleap` 或 `HKCU\Software\Pathleap` 的 `InstallScope` 值（64 位视图），设置界面据此显示当前模式。

安装完成可选择立即启动 UI（以原用户身份启动，不继承安装时的提权）；UI 会按配置 `startServiceWithUi` 自动拉起同目录的
`Pathleap.Service.exe --console`，不需要单独启动服务。

**静默安装/卸载**：`Pathleap-<版本>-win-x64-setup.exe /VERYSILENT /ALLUSERS` 或 `/CURRENTUSER`；卸载用安装目录下的
`unins000.exe /VERYSILENT`。所有用户模式的卸载需要提权。

**卸载与用户数据取舍**：

- 程序文件、开始菜单/桌面快捷方式、卸载注册项一律清除；安装范围注册值一并删除。
- 配置、日志、索引缓存（`%LOCALAPPDATA%\Pathleap`）**默认保留**：升级或重装后可以直接沿用索引与配置。
- 交互式卸载会询问「是否同时删除当前用户的配置、日志与索引缓存」；选「是」才删除该目录。静默卸载默认保留。
- 「所有用户」模式只删除**执行卸载的这位用户**的数据，其他用户的数据保留。
- 需要彻底清理时，请先退出 Pathleap，再删除各用户的 `%LOCALAPPDATA%\Pathleap` 即可。

### 2.2 运行前提

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 系统 | Windows 10/11 x64 | 安装包声明 `x64compatible` |
| .NET | .NET 8 Desktop Runtime | 当前产物是框架依赖构建，未自带运行时 |
| Windows App SDK | Windows App Runtime 2.6.5 | UI 是 unpackaged WinUI 3 应用 |
| 管理员 | **运行非必需**；仅「所有用户」安装需要 | 非管理员可正常搜索；USN 主路径需要管理员或 LocalSystem，非管理员 `auto` 会降级目录遍历 |

### 2.3 首次使用：启动后自动建索引

服务启动即自检索引文件，**不存在或构建时间超过 7 天**就在后台自动开始构建，不需要用户操作，
也不阻塞 UI 连接管道。索引文件落在 `%LOCALAPPDATA%\Pathleap\service\index\<卷>.plidx`。

- **进度可见**：主窗空态与底栏显示「索引构建中 · 已扫描 N 条」（合成索引带百分比），设置页同步显示
  阶段、条目数与警告；UI 每秒轮询服务状态。
- **构建期间可搜**：重建时保留上一次索引，查询继续可用，结果页与底栏注明「结果来自上一次索引（N 条）」；
  首次构建尚无旧索引时，搜索会明确返回「索引构建中：…，完成后自动可搜」。
- **降级不静默**：非管理员拿不到卷句柄时自动降级为目录遍历，状态带警告「USN 主路径不可用：…；已降级为目录遍历」，
  底栏显示「降级模式」。
- **失败不静默**：构建失败且旧索引可装载时保持可用，并给出「上次索引仍可用（N 条）；本次构建失败：原因」；
  没有可用旧索引时置为错误态，设置页显示失败原因。
- **手动重建**：设置 → 搜索范围与索引 →「重建索引」，请求立即回执，进度与自动构建一致。

实测（本机 200% 缩放，C: 目录遍历）：清空索引后冷启动，启动 2 秒内自动开始；1,187,262 条约 58 秒完成，
索引 34.5 MB；完成后查询 `explorer` 24 条、0.3 ms；索引未过期时重启直接 `ready` 并跳过构建。
详见 [1.0.4-发布说明](docs/1.0.4-发布说明.md) §2。

需要单独为某个目录建索引时仍可用基准脚本（会覆盖同卷 `.plidx`，先备份）：

```powershell
pwsh -File .\tools\Run-LpIndexBench.ps1 -LpBuild -LpMode walk -LpRoot 'C:\Windows' -LpIterations 1
```

热键默认**连续两次 `Ctrl`**（380 ms 判定窗口），可在 `%LOCALAPPDATA%\Pathleap\config.json` 的 `uiHotkey` 修改，
也可在设置 → 快捷键里从预置清单切换（双击 Ctrl/Alt/Shift 与三种组合键），选中立即生效。
搜索窗失焦自动隐藏，`Esc` 隐藏并清空查询，`Enter` 打开选中项（目录用资源管理器、文件用系统默认程序）。

### 2.4 始终以管理员身份运行

设置 → 更新 →「安装与权限」卡片里可以开启「始终以管理员身份运行」，也可以在该卡片查看当前安装模式
（仅当前用户 / 所有用户 / 便携版）、维护者与安装目录。安装范围切换需要重新运行安装包，卡片里已写明。

实现方式：开关打开时注册一个**无触发器的计划任务**（`Pathleap-Elevated-<用户SID>`，`RunLevel=HighestAvailable`），
之后每次启动由未提权的启动器写交接文件、用 `schtasks /Run` 拉起该任务，再以 `--elevated-launch` 恢复原参数。
**不使用 `HKCU\...\Run` 注册表项**，因此不会出现「登录后静默提权」的行为。注册/取消任务各需要一次 UAC。

代价与限制（界面中同步提示，不能隐去）：

- **UIPI**：提权后的窗口完整性级别更高，资源管理器（未提权）无法把文件/文件夹拖进提权窗口；
  需要拖放时请关闭该开关。这是 Windows 的跨完整性级别限制，不是 Pathleap 自身的 bug。
- 计划任务按用户隔离；同一台机器上的其他用户需要各自开启。
- 便携版同样可用，但由于没有安装范围注册值，设置卡片会显示「便携版」。

已验证：开启后 `--tray` 由计划任务拉起（`elevated=True`），`--status` 与 `--quit` 经命名管道转发成功，
删除任务后回到普通权限且功能正常；详见 `docs/1.0.2-发布说明.md` §3。**未验证**：在设置界面用鼠标点击开关完成
「注册任务 → 重启提权」的完整链路（该控件没有可自动化的 UIA Invoke），以及提权后资源管理器拖放的实拍。

### 2.5 快速切换（Ctrl+G）与文件对话框注入

任意位置按 `Ctrl+G` 打开快速切换浮层：列出已打开的文件夹窗口与最近访问，`1`–`6` 直选、`Enter` 跳转、`Esc` 关闭。
默认热键可在 `config.json` 的 `quickSwitchHotkey` 修改；注册失败（被其它程序占用）时会写日志并在托盘提示。

如果按下 `Ctrl+G` 时前台是系统标准的「打开 / 另存为 / 选择文件夹」对话框（窗口类 `#32770`），浮层页脚会显示
「对话框：打开 · 将注入路径」。选中文件夹后，Pathleap 会把路径写回对话框的文件名框并回车，让对话框直接跳转。
没有检测到对话框时，页脚显示「未检测到文件对话框」，选中项改为在资源管理器打开。

注入只针对标准对话框；浏览器上传、Electron 自绘选择器等不会被识别，也不会误写路径。
实现与实测细节见 [1.0.3-发布说明](docs/1.0.3-发布说明.md)。

## 3. 索引与搜索的工作方式

### 3.1 索引来源：USN 主路径 + 降级

1. `mode=usn`：打开卷句柄 `\\.\C:` 的 `GENERIC_READ`，用 `FSCTL_ENUM_USN_DATA` 枚举 MFT 记录，直接得到
   文件名、父引用、大小与时间。**需要管理员或 LocalSystem**；非管理员会得到 Win32 错误 5。
2. `mode=auto`：优先 USN；拿不到卷句柄或 USN 失败时自动降级为目录遍历（`walk`），日志留痕，
   并把降级原因作为警告写入索引状态，界面底栏显示「降级模式」、设置页显示原因（自动建索引默认走 `auto`）。
3. `mode=walk` / 非卷路径：从指定根目录递归枚举，适合只索引某个目录或没有管理员权限时使用。

USN 实测（管理员，整卷 `C:\`）：1,110,379 条、构建 10,822 ms、索引 32.70 MB（30.88 B/条），
来源标记 `usn:\\.\C:` 证明走的是主路径而不是降级。数据来源：`docs/1.0.0-发布说明.md` §1.3。

### 3.2 索引文件格式（v4）

```
[Header 256B][Record 16B × N][PrefixLens 1B × N][名字后缀区]
```

- 记录 16 字节：`NameOffset u32 / ParentIndex i32 / SizeAndFlags u32 / LengthDepth u16 / ModifiedDays u16`。
- 名字按「折叠小写」排序；每 5 条一组做公共前缀编码，组首存全名，其余只存前缀之后的字节。
- 读取侧 `MemoryMappedFile` + `AcquirePointer`，查询零拷贝；不反序列化整表。
- 体积实测：`C:\` 全卷 30.88 B/条；`C:\Windows` 43.68 B/条；`C:\Windows\WinSxS` 48.72 B/条；
  5M 合成 25.46 B/条。按真实名字分布外推 5M 约 154 MB。数据来源：`docs/M2-索引与搜索报告.md` §10.2。

### 3.3 查询

- T0 完全相等（tier 100）、T1 前缀（85）、T2 子串（70）；多 token 按 AND 组合。
- 前缀用二分（`LowerBound` / `UpperBoundOfPrefix`）；子串用 `SearchValues<byte>` + 分片并行扫描。
- 结果直接按 `(tier, 深度)` 分桶，不做全量排序；前缀命中已够填满结果集时跳过整段子串扫描。
- junction 命中按前缀块成组遍历，先用后缀首字节快速否决。

实现入口：`src/Pathleap.Shared/Index/SearchEngine.cs`、`IndexSnapshot.cs`。

## 5. 目录结构与两个进程

```
Pathleap/
├── src/
│   ├── Pathleap.Shared/     品牌常量、配置、日志、IPC 协议、索引格式/构建/查询
│   ├── Pathleap.Service/    常驻索引服务：管道、索引装载/构建、搜索；--build-once 子进程入口
│   └── Pathleap.UI/         WinUI 3：托盘、全局热键、搜索窗、结果列表、唤醒基准
├── installer/               Inno Setup 脚本与中文语言文件
├── tools/                   PowerShell 构建/打包/测试/基准脚本（自定义变量统一 Lp 前缀）
├── docs/                    里程碑报告、发布说明、版本规则、发布检查清单
└── .github/workflows/       CI：构建、打包 zip/安装包、tag 发布 Release
```

| 进程 | 职责 | 生命周期 |
| --- | --- | --- |
| `Pathleap.UI.exe` | 单实例互斥、托盘、全局热键、搜索窗与结果列表、把 `--show/--status/--bench/--quit` 转发给主实例；按配置拉起服务 | 常驻托盘；可由用户退出 |
| `Pathleap.Service.exe` | 命名管道控制面（`PING/STATUS/SEARCH/INDEX_STATUS/INDEX_BUILD`）、索引装载、构建与查询 | 由 UI 拉起（`--console`），UI 退出时一并结束；也可手动以控制台/SCM 模式运行 |

服务 IPC 只绑定命名管道，不监听网络端口。索引构建通过 `Pathleap.Service.exe --build-once <mode> <root> <output>`
短生命周期子进程执行，父进程只读取 `.result.json` 摘要。

## 6. 构建、打包与 CI

```powershell
# 编译（先跑脚本变量命名检查，并把服务产物复制进 UI 输出目录）
pwsh -File .\tools\Build-Lp.ps1 -LpConfiguration Release

# 便携 zip：dist\Pathleap-<版本>-win-x64.zip
pwsh -File .\tools\Package-Lp.ps1

# 安装包：dist\Pathleap-<版本>-win-x64-setup.exe（需要 Inno Setup 6）
pwsh -File .\tools\Package-LpInstaller.ps1
```

本机安装包编译可用 Inno Setup 6（CI 使用 `choco install innosetup`）；脚本会依次查找 PATH、
`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`、`%ProgramFiles%\Inno Setup 6\ISCC.exe`。

CI（`.github/workflows/build.yml`）：main/PR 构建并上传 `Pathleap-<版本>-win-x64` 产物（zip + setup）；
tag `v<版本>` 触发时以 tag 版本注入构建，并额外创建/更新私有仓库的 Release（zip 与 setup）；
再按需推送到公开发布仓库：上传产物、生成并签名 `latest.json`、上传清单。
公开仓库这一步需要 `PATHLEAP_RELEASES_PAT` 与 `PATHLEAP_SIGNING_KEY` 两个 secret，
缺任一则**明确跳过并给出 warning**，不会静默失败。方案取舍与凭据步骤见
[更新源与签名](docs/更新源与签名.md)。

## 7. 版本号规则

版本号唯一来源是 [Directory.Build.props](Directory.Build.props) 的 `PathleapVersion`；程序集版本、程序内显示、
zip/安装包名、CI 产物名都由它派生。规则摘要：

- 格式 `<major>.<minor>.<patch>[-alpha<N>]`；`major` 不设上限，`minor` / `patch` 取 0–10，超过 10 向前进位。
- 预发布用 `alphaN`；正式版落到数字版本（当前 `1.0.4`）。
- tag 带 `v` 前缀（`v1.0.4`）；升级用 `pwsh -File .\tools\Next-LpVersion.ps1 -LpBump patch -LpApply`。
- 完整进位示例与「下一版是什么」见 [docs/版本号规则.md](docs/版本号规则.md)。

## 9. 已知限制与未完成项

1. **自动建索引只在服务启动时判定一次**：缺失或构建超过 7 天才重建；运行期文件变化不自动触发，
   需在设置页点「重建索引」。首次构建完成前进度可见，但没有旧索引时搜索只能返回「索引构建中」提示。
2. **索引是单卷/单文件**：`LoadLatest` 只装载最新的一个 `.plidx`，多卷合并未实现。
3. **无增量更新**：USN 只做全量枚举，文件增删改后需要重新构建索引。
4. **无 SCM 服务安装**：服务随 UI 启动；不随系统开机常驻。
5. **更新源已改为公开发布仓库，流水线未在 CI 验证**：客户端读 `latest.json` 并验签、下载校验 SHA256；
   公开仓库发布步骤需 `PATHLEAP_RELEASES_PAT` + `PATHLEAP_SIGNING_KEY`，本轮只做本地 dry-run。
   后台静默安装与预发布通道未接入。
6. **文件对话框注入仅覆盖标准对话框**：系统 `#32770` 的打开/另存为/选择文件夹已接入；浏览器上传、Electron 自绘选择器等不识别，浮层会提示「未检测到文件对话框」并退回资源管理器打开。
7. **窗口圆角为系统值（约 8 DIP）**：与设计稿 14 DIP 存在差异，取舍理由见 `docs/界面验收报告.md`。
8. **前台唤醒基准待复测**：alpha5 重试修复没有有效前台样本，现有最新前台数据仍是 M1 的 1000 次结果。
9. **`Enter` 打开目标未前台验收**：选中项到路径的映射已由后台测试覆盖，真正拉起资源管理器/默认程序的最后一步未自动化。
10. **真实整卷索引在本地测试中会被覆盖**：基准脚本会把 5M 合成索引写到同一路径；需要真实卷数据时重新跑 USN 构建。

## 10. 文档维护约定

**每个里程碑完成、每次发版，必须同步更新 README 的对应章节**：

- 版本号、能力清单（已实现 / 未完成）、性能实测数据、已知限制；
- 新增或改变的安装/构建方式、产物名；
- 所有数字必须来自 `docs/` 下的实测报告，注明口径（后台 / 前台）与环境，不写未验证的能力。

**界面里程碑验收标准（硬性）**：任何涉及界面的里程碑，必须附真实应用截图与设计稿（`docs/design-reference.html`）的并排对照，并逐项列出「设计稿要求 / 当前实现 / 差距 / 是否解决」；没有截图对照的界面改动不算完成。截图通道、缩放比例、会话状态需在报告中写明；无法实测的项必须标注「未验证」或「被环境挡住」，不得写成已完成。

发版时逐项核对 [docs/发布检查清单.md](docs/发布检查清单.md)，其中「README 与当前版本一致」为必过项。

## 脚本安全约定

- 所有 PowerShell 自定义变量以 `Lp` 开头；`tools/Test-LpVariableNames.ps1` 用 AST 检查，`Build-Lp.ps1` 会先执行。
- 删除/清理只走 `tools/Lp.Safety.psm1` 的 `Remove-LpItemSafely`：路径白名单、`-WhatIf`、删除前打印绝对路径。
- 测试默认后台/离屏（UI `--tray`、服务 `--console`）；前台唤醒基准必须显式 `-LpAllowForeground`，并且每轮集中跑一次。
