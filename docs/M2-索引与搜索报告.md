## 3. 索引

### 3.1 文件格式

单文件三段式：`[Header 256B][Records N × 20B][NameArena UTF-8]`。

- Header 含 magic、formatVersion、条目数、名字区偏移、构建时间、来源标记。
- 记录从 32 字节压到 20 字节（`NameOffset u32 / NameLength u16 / Depth u8 / Flags u8 / ParentIndex i32 / SizeKb u32 / ModifiedUnixSec u32`）：体积与修改时间只用于结果展示，不需要字节级/毫秒级精度；深度用 1 字节（路径深度不会超过 255）。
- 条目按「折叠小写名字 → 原名」排序落盘，因此前缀查询可以直接在名字区二分，子串扫描也天然按名字升序。
- 读取侧 `MemoryMappedViewAccessor` + `AcquirePointer`，查询零拷贝；装载只校验头和映射，500 万条目装载 1.09 ms。
- 格式版本 2：旧缓存（32 字节记录）会在装载时报错并提示重建，不会读出错位数据。

### 3.2 合成索引（500 万条目，查询性能的基准数据集）

| 版本 | 记录大小 | 构建耗时 | 文件体积 | 装载 |
| --- | --- | --- | --- | --- |
| 旧格式 | 32 B | 16 327 ms | 238.3 MB（249 903 561 B） | 0.93–3.40 ms |
| 新格式 | 20 B | 7 046 ms（另一次 8 879 ms） | 181.1 MB | 1.09 ms |

构建耗时下降同时来自记录变窄（落盘量 -24%）与真实目录 I/O 之外的纯内存生成。

### 3.3 真实目录（降级遍历源）

| 目录 | 条目数 | 构建耗时 | 文件体积 | 每条字节 |
| --- | --- | --- | --- | --- |
| `C:\Windows\System32` | 27 913 | 358 ms | 1.8 MB | — |
| `C:\Windows` | 241 559 | 5 994–9 968 ms | 16.3 MB | 70.8 B |

同一条目在磁盘缓存命中与未命中之间相差约 1.6 倍；上表给的是观测区间。

### 3.4 USN 主路径（阻塞）

`FSCTL_ENUM_USN_DATA` / `FSCTL_READ_USN_JOURNAL` 需要卷句柄的 `GENERIC_READ` 权限，本机账户非管理员：

- `CreateFileW("\\.\C:", GENERIC_READ)` 返回 `ERROR_ACCESS_DENIED (5)`，主路径无法在这台机器上实测。
- 代码层面的行为已验证：`usn` 模式抛 `UsnAccessException` 后按配置降级到 `walk`，`auto` 模式自动降级且日志留痕。
- 要实测主路径，需要**一次**管理员身份（或 LocalSystem 服务身份）运行 `INDEX_BUILD Mode=usn`，预计 5M 条目 MFT 枚举 + 落盘 10–20 s。

## 4. 查询性能（后台口径，服务端 `QueryMs`）

数据集为 500 万合成条目，每查询 40 次（先预热 1 次），nearest-rank 百分位：

| 版本 | 关键改动 | `report` | `.dll` | `zzzzzz` | `report dll` |
| --- | --- | --- | --- | --- | --- |
| V1（Debug） | 逐条目 `FoldContains` + 候选全排序 | 283 / 357 | 726 / 962 | — | — |
| V2（Debug） | (tier, 深度) 分桶，去掉全排序与巨型辅助数组 | 65.8 / 73.8 | 87.2 / 96.7 | 63.2 / 66.5 | — |
| V3（Debug） | 名字区整块向量化扫描（`SearchValues<byte>` + `IndexOfAny`），命中后二分定位条目 | 13.1 / 19.5 | 51.6 / 76.0 | 3.0 / 3.4 | 20.2 / 25.9 |
| V4（Release） | 扫描位置单调 → 条目游标替代二分；分片命中上限；单 token 免去重字典；修复前缀区间二分 | 7.08 / 9.49 | 6.53 / 10.37 | 2.63 / 3.84 | 14.20 / 21.83 |
| V5（Release，新格式） | 记录 20 B（体积/时间降精度） | 9.00 / 13.67 | 6.31 / 17.66 | 2.46 / 4.20 | 11.74 / 18.39 |

表中为 P50 / P95（ms）。V4→V5 无查询逻辑改动，差异属运行间波动；两版均满足 P95 ≤ 30 ms。

另外两个数据点：

- `project_0000123`（单条精确命中）V4 5.32 / 6.70，V5 8.80 / 16.46。
- 管道往返 P95 约 30 ms，其中绝大部分是 PowerShell 客户端建连与 JSON 开销，不是服务端查询时间。

### V4 中修掉的一个真实缺陷

`UpperBoundOfPrefix` 原先在 `[0, count)` 上二分「是否以 token 为前缀」。该谓词在数组上是 **false → true → false**，并不单调：前缀区之前的大量 false 会把右界一路压到 0，导致

- 前缀命中永远为空，所有结果都从子串路径产出（`tier` 恒为 70）；
- 别名/精确匹配相对子串没有任何排序优势。

修复为只在 `[LowerBound, count)` 区间内二分（该区间内谓词单调），并以 `project_0000123 → tier=100/85` 的抽查确认恢复。

## 5. 内存

| 时点 | 私有字节 | 工作集 |
| --- | --- | --- |
| 服务启动（未装载索引） | 7 MB | — |
| 5M 合成构建完成后 | 1 552 MB | 1 500 MB |
| 随后重建 241k 条真实索引 | 1 115 MB | 1 064 MB |

映射索引本身不占私有提交，查询期常驻开销很小；上表的大头是构建期临时结构。构建收尾已加一次 `GC.Collect`，但 .NET 的已提交段不会立刻归还操作系统，**私有工作集不会回落到启动水平**。可选缓解（列为 M3 待办，不在本次改）：构建放进短生命周期子进程、或对服务设置更激进的回收策略。

## 6. 唤醒延迟（前台口径）

修复内容：`ShowCore` 显示后若前台仍不是本窗口，120 ms 后重试，最多 2 次；重试时用 `AttachThreadInput` 把输入队列挂到当前前台线程，再 `BringWindowToTop` / `SetForegroundWindow` / `SetFocus`。

| 数据 | M1 基线（1000 次，Release） | 本次（1000 次，Release） |
| --- | --- | --- |
| 冷样本（第 1 次唤醒） | **失败**（foregroundOk=false / window-not-visible / 焦点超时），两轮均如此 | 有效：首帧 29.929 / 焦点 43.200 / 可输入 71.670 ms |
| 首帧 P50 / P95 | 12.446 / 17.866 | 17.877 / 24.416 |
| 获得焦点 P50 / P95 | 16.645 / 21.775 | 21.868 / 29.970 |
| 可输入 P50 / P95 / max | 33.673 / 41.739 / — | 35.771 / 49.724 / 89.994 |
| 有效样本 / warm 失败 | 999 / 0 | 1000 / 0 |

结论：

- 冷样本从「必然失败」变为「可用」，这是本次修复的直接收益。
- warm 分位数比 M1 高 2–8 ms，本次未做归因实验，且采集时用户正在使用本机（另一轮并行采集因用户操作出现 29/1000 失败），不能视为代码回归；**需要在无干扰时段、经用户同意后单独复测**才算定论。
- 重试路径在本次采集里没有被触发（日志中 0 条「前台锁重试」），说明首次激活本身已成功；重试代码保留作为前台锁竞争的兜底。

`tools\Test-LpSmoke.ps1 -LpConfiguration Release -LpStop`：13/13 通过，被测实例以 `--tray` 启动、全程无窗口、无键鼠注入。其中索引状态检查改为走 `INDEX_STATUS`（`state=ready, entries=241559, source=walk:C:\Windows`）。

## 8. 未达成项与风险

1. **索引体积对真实文件名的外推超标**：真实目录 70.8 B/条目（`C:\Windows`），5M 条目约 354 MB，高于 220 MB 目标；合成数据 36.2 B/条目（名字短）才达标。名字区占总量的四成以上，下一步可做**名字前缀编码（front-coding）或用 32 位名称池去重**，代价是查询侧名字解码，需要在 30 ms 预算内验证。
2. **USN 主路径未实测**：原因与所需条件见 §3.4，属于环境限制而非代码缺陷。
3. **构建后私有工作集不回落**：见 §5，峰值 1.5 GB 对长驻服务偏高。
4. **真实目录覆盖不足**：本机只测了 `C:\Windows`（241k）与 `System32`（28k），没有百万级真实卷样本；现有数据只能说明线性趋势。

## 9. 复现

```powershell
# 构建（含脚本变量命名检查）
pwsh -File .\tools\Build-Lp.ps1 -LpConfiguration Release

# 后台口径：500 万合成索引 + 查询分位（不起窗口、不碰前台）
pwsh -File .\tools\Run-LpIndexBench.ps1 -LpBuild -LpMode synthetic -LpIterations 40

# 后台口径：真实目录（遍历源）
pwsh -File .\tools\Run-LpIndexBench.ps1 -LpBuild -LpMode walk -LpRoot 'C:\Windows' -LpIterations 20

# 后台口径：冒烟
pwsh -File .\tools\Test-LpSmoke.ps1 -LpConfiguration Release -LpStop

# 前台口径（会反复抢前台，默认拒绝；仅在确认可占用前台时使用）
pwsh -File .\tools\Run-LpBench.ps1 -LpSamples 200 -LpConfiguration Release -LpAllowForeground
```
