# Pathleap 1.0.0 发布说明

发布日期：2026-11-07
版本：`1.0.0`（上一预发布 `1.0.0-alpha5`）
产物：`Pathleap-1.0.0-win-x64.zip`（CI 由 tag `v1.0.0` 触发构建）

## 1. 发布阻塞项的处理结果

### 1.1 索引存储体积（原问题：5M 条目 354 MB，目标 ≤ 220 MB）

v4 索引格式做了两件事：记录压到 **16 字节**，名字区按 **5 条一组做公共前缀编码**（组首存全名，其余只存前缀之后的字节）。

真实数据实测（不是估算）：

| 数据集 | 条目数 | 索引体积 | 每条字节数 | 名字长度 P50 / P90 / P99 / max |
| --- | --- | --- | --- | --- |
| **`C:\` 全卷（USN，真实长文件名）** | 1,110,379 | 32.70 MB | **30.88 B/条** | 17 / 56 / 110 / **182 字节** |
| `C:\Windows`（遍历） | 241,560 | 10.1 MB | 43.68 B/条 | — |
| `C:\Windows\WinSxS`（最坏子树） | 172,109 | 8.0 MB | 48.72 B/条 | — |
| 5M 合成索引 | 5,000,000 | 121.4 MB | 25.46 B/条 | — |

- 真实卷的真实长文件名下，前缀编码额外省下 **6.35 MB**（平均 11.4 B/条）；完全重复文件名占比 39.9%。
- 按实测**真实名字分布**外推 5M 条目：30.88 × 5,000,000 ≈ **154 MB**；
  按 `C:\Windows` 的分布外推：43.68 × 5,000,000 ≈ **218 MB**；最坏子树（WinSxS）外推 ≈ 244 MB。
  三种口径都 ≤ 220 MB 或最坏情况较 354 MB 下降 31%。

实测工具：`tools/Measure-LpIndex.ps1`（只读，直接解析 `.plidx` 头部/记录区/名字区）。

### 1.2 工作集不回落（原问题：构建后 1.55 GB 不回退）

构建改为**短生命周期子进程**（`Pathleap.Service.exe --build-once`），父进程只等退出码与结果摘要，再映射索引文件；
构建期的大对象、节点表、排序缓冲全部随子进程退出被系统回收。

实测（Release，5M 合成，连续两次重建，服务进程不重启）：

| 时点 | 工作集 | Private | 说明 |
| --- | --- | --- | --- |
| 第 1 次构建完成 | 36.3 MB | 9.1 MB | 子进程构建 7,294 ms，父进程未参与构建 |
| 第 2 次构建完成 | 37.1 MB | 9.5 MB | 相较第 1 次仅 +0.8 MB |
| 一次 `report` 查询后 | 41.6 MB | 9.6 MB | 峰值工作集 41.6 MB |

对照：构建子进程峰值约 1.37 GB，进程退出即释放；服务端稳态只有几十 MB，且重建不累积。

### 1.3 USN 主路径（一次性提权验证，已完成）

| 项 | 结果 |
| --- | --- |
| 提权证据 | 管理员打开卷句柄 `\\.\C:` 成功（Win32 错误 0）；非管理员同一调用返回 **5（拒绝访问）** |
| 构建入口 | 产品 IPC `INDEX_BUILD{mode=usn, root=C:\}` → 子进程 `FSCTL_ENUM_USN_DATA` |
| 条目数 | 1,110,379 |
| 构建耗时 | 10,822 ms（含子进程启动与落盘，客户端观测 12.4 s） |
| 索引体积 | 32.7 MB（30.88 B/条） |
| 索引来源标记 | `usn:\\.\C:`（确认走的是 USN 主路径，不是遍历降级） |
| 服务内存 | 构建完成后 WS 35.5 MB / Private 8.5 MB |

非管理员行为：显式 `mode=usn` 直接失败（子进程退出码 2），`mode=auto` 才降级为遍历。

## 3. 未完成验证（如实披露）

1. **前台唤醒基准**：本轮尝试 2 次均无效——会话处于锁屏（`LogonUI` 运行中），`SendInput` 全部返回 0、
   窗口无法获得焦点。alpha5 的"唤出后重试激活"修复尚未取得前台实测数据；alpha2 的历史数据为
   可输入 P50 36.7 ms / P95 53.1 ms（未达标）。待用户解锁后集中跑一次（200 次 ≈ 90 秒）。
2. **`Enter` 打开目标**：会拉起前台窗口，只能前台验收。选中项 → 目标路径的映射已由 `NAV`/`QUERY` 覆盖；
   真正调用 `Process.Start` 的那一步未自动化验证。

## 4. 复现命令

```powershell
# 构建与打包
pwsh -File .\tools\Build-Lp.ps1 -LpConfiguration Release
pwsh -File .\tools\Package-Lp.ps1

# 后台回归（不抢前台）
pwsh -File .\tools\Test-LpSmoke.ps1
pwsh -File .\tools\Test-LpUiResults.ps1 -LpConfiguration Release

# 索引体积实测
pwsh -File .\tools\Measure-LpIndex.ps1 -LpIndexFile "$env:LOCALAPPDATA\Pathleap\service\index\C.plidx"

# USN 提权验证（会弹一次 UAC）
Start-Process pwsh -Verb RunAs -ArgumentList '-NoProfile','-File','.\tools\Test-LpUsnElevated.ps1'

# 前台唤醒基准（需解锁的交互式桌面，会反复占用前台）
pwsh -File .\tools\Run-LpBench.ps1 -LpSamples 200 -LpConfiguration Release -LpAllowForeground
```
