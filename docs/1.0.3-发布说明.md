# Pathleap 1.0.3 发布说明

发布日期：2026-11-07
版本：`1.0.3`（上一正式版 `1.0.2`）
tag：`v1.0.3`

版本号按 [版本号规则](版本号规则.md) 从 `1.0.2` 升 patch 得到 `1.0.3`（未超过 10，不进位）。

## 1. 本次变更

1. **全局 `Ctrl+G`**：新增第二个全局热键，任意位置按下即唤出快速切换浮层；默认 `Ctrl+G`，
   可在 `%LOCALAPPDATA%\Pathleap\config.json` 的 `quickSwitchHotkey` 修改。注册失败（被占用）时写日志并在托盘提示。
2. **标准文件对话框注入**：按下热键时如果前台是系统 `#32770` 的「打开 / 另存为 / 选择文件夹」对话框，
   浮层页脚显示「对话框：打开 · 将注入路径」；选中文件夹后把路径写回文件名输入框并回车，让对话框直接跳转到该目录。
3. **前台激活修复**：浮层显示后主动抢前台（`AttachThreadInput` + `SetForegroundWindow`），避免热键触发后焦点仍留在文件对话框上。
4. **设置页文案同步**：快捷键页的 `Ctrl+G` 由「未接入」改为「已接入」，并说明可通过 `quickSwitchHotkey` 修改。
5. **README 如实标注**：能力表区分「能用 / 未接入」，注入只覆盖标准对话框这一限制写入「未完成项」，不再出现含糊表述。

## 3. 文件对话框注入实测

测试对象：WinForms 标准 `OpenFileDialog`（窗口类 `#32770`，标题 `Open`，初始目录 `C:\Windows`），
这是系统公共对话框，与资源管理器「打开」使用的是同一套控件。

| 步骤 | 结果 |
| --- | --- |
| 识别对话框 | 窗口类 `#32770` + 标题白名单命中，日志 `dialog=打开, title=Open` |
| 浮层页脚徽标 | 显示「对话框：打开 · 将注入路径」（强调色），截图 `docs/shots/23` |
| 选中文件夹后注入 | `WM_SETTEXT` 写入目标路径，聚焦文件名框，发送 `Enter` |
| 对话框反应 | 面包屑从 `C:\Windows` 跳转到 `Pathleap\docs`，对话框保持打开，截图 `docs/shots/22` |
| 无对话框/注入失败 | 回退为资源管理器打开，日志留痕，不误写路径 |

实现要点：

- 只处理 `#32770`，并用标题白名单区分「打开 / 另存为 / 选择文件夹」；「打开方式」等同样使用 `#32770` 的对话框被显式排除。
- 文件名输入框优先取 `ComboBox` / `ComboBoxEx32` 内的可见、非只读 `Edit`；找不到时取位置最靠下的可见 `Edit`
  （新版公共对话框顶部还有搜索框，靠下的才是文件名框）。
- **只发送 `Enter`，不发送 `WM_COMMAND(IDOK)`**：发送 `IDOK` 会让「打开文件」对话框把目录当成已选文件直接关闭；
  只回车则被当作「进入该目录」，对话框保持打开，「选择文件夹」对话框按回车则是选中并关闭，均符合预期。

**未验证 / 已知限制**：

- 浏览器上传、Electron 自绘选择器等非 `#32770` 选择器不会被识别，浮层如实显示「未检测到文件对话框」并退回资源管理器；
  不做猜测式注入，避免写错控件。
- 「另存为」「选择文件夹」两类对话框已按同一套控件结构实现，但本轮实拍只覆盖「打开」；其余两类未单独截图。

## 4. 缩放与最大化

- **125% / 150% 缩放：未验证**。本机固定 200%，改缩放需注销会话，本轮不执行。代码按 DIP 布局，但没有这两档的真实像素证据。
- **最大化：不适用**。主窗固定尺寸且 `IsMaximizable=false`，不存在最大化态；文档不再保留除此之外的模糊表述。
