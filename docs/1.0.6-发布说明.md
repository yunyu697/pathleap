# Pathleap 1.0.6 发布说明

发布日期：2026-11-08
版本：`1.0.6`（上一正式版 `1.0.5`）
tag：`v1.0.6`

版本号按 [版本号规则](版本号规则.md) 从 `1.0.5` 升 patch 得到 `1.0.6`（未超过 10，不进位）。

**本版只做缺陷修复，不新增功能**：`1.0.5` 的安装包在默认安装目录（位于 C:）下，
首次启动与手动「重建索引」都只会扫到安装目录本身（约 70 条），搜索基本不可用。
`1.0.5` 的 tag 已发布不能移动，因此以 `1.0.6` 重新发出修复。

## 1. 缺陷：C: 默认安装目录下索引只扫到安装目录

**影响面**：把 Pathleap 装在 C: 盘的用户（默认安装目录 `%LOCALAPPDATA%\Programs\Pathleap` 就在 C:）。
表现为：

- 首次启动自动构建在 0.1 秒内「完成」，条目数只有几十条（安装目录自身的文件与子目录）；
- 此后手动「重建索引」结果相同，索引状态与搜索结果都停在几十条；
- 装在非 C: 盘、或从非 C: 工作目录启动的实例不受影响，因此开发期与既有验收未暴露。

**根因**：[DirectoryIndexSource.cs](../src/Pathleap.Shared/Index/DirectoryIndexSource.cs) 把
`Path.GetFullPath("C:\\")` 的结果做了 `TrimEnd('\\')`，得到 `C:`。`C:` 是**盘符相对路径**，
实际指向「进程在 C: 盘上的当前目录」；索引构建子进程的工作目录正是安装目录，于是整卷被误扫成该目录。

**修复**（提交 `4c6247e`）：保留根路径的尾分隔符后再入队，日志里的来源字符串仍显示 `walk:C:`。

## 2. 附带修复：设置页索引文件名

设置页原先硬编码「索引文件 index.v4.db」，实际落盘是 `index\C.plidx`。改为读取服务状态里的
`FilePath` 取文件名（提交 `a20b715`），修复后显示「索引文件 C.plidx」。

## 3. 验证

（本节数字在 1.0.6 的 Release 资产上实测后回填。）

- 源码构建与冒烟测试见下方「构建与测试」。
- 真实安装验证：1.0.6 安装包默认装到 C:，首次启动后索引应达到百万量级。

## 4. 升级建议

- `1.0.5` 用户请直接升级到 `1.0.6`；升级会结束旧进程、覆盖程序文件，用户数据（配置/日志/索引）保留。
- 由于旧索引本身就是「几十条」的错误结果，升级后建议在设置 → 搜索范围与索引 里点一次「重建索引」；
  1.0.6 也会在索引过期（7 天）时自动重建。
- 从 `1.0.0`–`1.0.4` 升级：这些客户端不验签、不校验 SHA256，建议手动下载 `1.0.6` 安装包升级；
  `1.0.5` 起才具备 Ed25519 验签 + SHA256 校验。
