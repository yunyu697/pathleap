## 1. 快速切换栏吸附文件对话框底边

- 栏以 **owner 窗口**（`GWLP_HWNDPARENT`，不是 `SetParent`）贴在文件对话框底边外侧 2px，
  宽度取对话框可视宽度的一半并水平居中；`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`，显示与点击都不抢焦点。
- 由 `SetWinEventHook` 事件驱动挂载、随动与销毁：创建/显示/隐藏/销毁、位置变化、前台切换、最小化/还原。
- 多个对话框各有一条栏，owner 各自独立；键盘只路由给前台对话框那一条。
- 修复启动时已存在的对话框未纳入监视集合（不随动、关闭残留）的问题，并补前台切换时的死栏兜底清理。

实测（200% 缩放显示器，详见 [quick-switch-attach.md](quick-switch-attach.md)）：

| 场景 | 结果 |
| --- | --- |
| 初始挂载 | 对话框 1440×960，栏 706×220，宽比 0.49，间距 2px，居中偏差 0 |
| 拖动 +220,+90 | 栏位移与对话框完全一致 |
| 缩放对话框 | 栏实时重排（0.489 宽比，内容改为 3 列） |
| 两个对话框 | 各归其主，owner 可逐条核对，无串位 |
| 关闭一个 / 全部关闭 | 只销毁对应栏 / 全部立即消失 |

**已知限制**：只显示前台对话框对应的栏（后台栏隐藏），因此互叠时不会压住后方内容，但需先激活对话框才能点到它的栏；对话框最大化时栏回退到工作区顶部附近（只覆盖标题栏）。
理由见文档「已知限制」。

## 2. 启动后自动建索引

- 服务启动即自检：索引文件缺失或构建超过 7 天视为过期，**后台自动开始构建**，不等待用户触发，
  且不阻塞命名管道接受连接。
- 构建在短生命周期子进程执行，扫描与落盘阶段按节流（300 ms）回传进度；服务转发到状态快照，
  UI 每秒轮询显示「索引构建中 · 已扫描 N 条」/百分比与当前阶段，设置页同步显示。
- 构建期间保留上一次索引可搜，结果页与底栏注明「结果来自上一次索引（N 条）」；
  首次构建没有旧索引时，查询返回「索引构建中：…，完成后自动可搜」，不再误报「无结果」。
- 自动模式 USN 不可用时降级目录遍历，并把降级原因作为警告写入状态：底栏显示「降级模式」，
  设置页显示「USN 主路径不可用：…；已降级为目录遍历」。
- 失败不静默：旧索引可装载时保持可用并提示「上次索引仍可用（N 条）；本次构建失败：原因」；
  否则置错误态并保留失败原因。落盘前释放内存映射、替换文件带 15 秒重试，避免被映射文件无法替换。
- 设置页「重建索引」立即回执，进度展示与自动构建一致，不再让界面卡在等待。

冷启动实测（清空索引后启动，200% 缩放，`C:` 目录遍历）：

| 时点 | 观测 |
| --- | --- |
| t≈2 s | 自动开始构建，无需任何用户操作；状态 `state=building`、`phase=scan` |
| 构建中 | 主窗空态「索引正在构建 · 已扫描 200,000 条」；底栏「索引构建中 · 已扫描 200,000 条」；此时查询仍可返回旧索引结果 |
| t≈58 s | 完成：1,187,262 条、索引 34.5 MB、`buildMs=53,930`、来源 `walk:C:`，警告为 USN 权限不足降级 |
| 完成后 | `explorer` 查询 24 条、0.3 ms，底栏「索引就绪 · 1,187,262 条 · 降级模式」 |
| 重启（未过期） | 日志「索引构建于 …，未过期，跳过自动构建」，状态直接 `ready` |
| 重建中查询 | `state=building`、`scanned=200,000` 时仍返回 24 条（来自上一次索引） |
| 强制 `mode=usn`（非管理员） | 状态回落 `ready`，保留 1,187,745 条；`note=上次索引仍可用（…）；本次构建失败：打开卷句柄被拒绝（ERROR_ACCESS_DENIED）…`，`warning=构建失败：…`；随后查询仍 24 条 |

证据：构建中空态与完成后结果页见 `docs/shots/24-index-building.png`、`docs/shots/25-index-ready-results.png`；
构建进度、完成摘要与失败降级说明均由命名管道 `INDEX_STATUS` / `QUERY` 的返回字段记录（本轮日志原件保留在测试目录，未随仓库提交）。

**未验证 / 已知限制**：

- 运行期自动刷新只在 USN 索引上启用：用 `FSCTL_READ_USN_JOURNAL` 检测变更，安静 60 秒后自动重建，
  两次自动重建至少间隔 15 分钟；目录遍历索引或非管理员拿不到卷句柄时仍需手动「重建索引」。
  自动刷新是「变更检测 + 重建」，不是逐条增量打补丁。
- 首次构建完成前没有旧索引可搜，只有进度提示；没有做「部分结果」式的增量可搜。
- 未做管理员/USN 主路径下的自动构建实拍（本轮为目录遍历降级路径与强制失败路径）。

## 3. 默认双击 Ctrl 唤醒

- 默认唤醒方式从 `Ctrl+Alt+Space` 改为**连续两次 `Ctrl`**（380 ms 判定窗口、400 ms 长按阈值）；
  期间出现其它按键立即作废，不吞 `Ctrl+C/V`、`Ctrl+拖动` 与 `Ctrl+点击多选`。
- 低层键盘钩子收到的是左右区分虚拟键（`VK_LCONTROL`/`VK_RCONTROL`），统一归一到通用键，
  避免双击判定永远匹配不上而静默失效。
- 设置 → 快捷键提供预置清单（双击 Ctrl/Alt/Shift、三种组合键），每项标注适用与冲突风险；
  选中立即生效并写回 `config.json`，失败时回滚上一方式并同时写日志、托盘提示与设置页状态行。
- `config` v2 迁移：旧默认 `Ctrl+Alt+Space` 改为双击 `Ctrl`，用户自定义值保留。

实测：`keybd_event` 单次 Ctrl、长按 Ctrl 均不唤醒；连续两次 Ctrl 唤醒成功，`Esc` 后隐藏；
`Ctrl+C` 探针文本框复制/粘贴均正常（`CTRL-C-PROBE`），第二次双击仍可唤醒。
冒烟测试输出 `hotkey=双击 Ctrl registered=True`。
