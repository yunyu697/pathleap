# M3：结果列表与键盘交互

版本：`1.0.0-alpha5`（本文档记录 alpha5 的实现与验证）
前置：M2 的索引/查询能力，v4 索引格式与子进程构建（见 `M2-索引与搜索报告.md` §10）

## 1. 实现范围

| 能力 | 实现方式 |
| --- | --- |
| 搜索输入 → 结果列表 | 输入框 `TextChanged` 防抖 120 ms，停手后向服务管道发 `SEARCH`（`limit=24`），结果回填 `ListView` |
| 过期响应丢弃 | 每次查询递增代数号，响应回来时代数不一致直接返回，避免慢查询覆盖新结果 |
| 空状态 | 三种文案：未输入 / 无匹配 / 服务或索引未就绪（分别对应图标与提示） |
| 结果行 | 图标（目录/文件）、文件名、所在目录、大小（目录不显示大小）；数据来自服务端 DTO |
| 选择 | 默认选中第 0 行；`↑`/`↓` 移动，`PgUp`/`PgDn` 跨 6 行，上下界钳制并 `ScrollIntoView` |
| 打开 | `Enter`：目录用 `explorer.exe` 打开，文件交给系统默认程序；打开后隐藏窗口；失败回到错误态 |
| 隐藏 | `Esc` 隐藏并清空查询（清空会同步清空列表与计数） |
| 状态栏 | 服务连接状态 + 索引条目数/来源；结果区右上角显示「条数 · 服务端查询耗时 ms」 |

结果排序完全沿用服务的 tier 规则（100 精确 / 85 前缀 / 70 子串），UI 不再二次排序。

## 2. 后台验证口径

用户要求「不要在正常使用中抢前台」，所以 M3 的验证整条走后台：

- 被测实例：服务 `--console`（无窗口）+ UI `--tray`（不显示窗口、不注册可见窗口）
- 驱动方式：UI 控制管道的 `QUERY` / `NAV` 命令
  - `QUERY`：等价于在搜索框输入文本并等结果回来（设置文本 + 同步跑一次查询，不走防抖）
  - `NAV`：等价于按一次 `↑`/`↓`（走的是同一个 `MoveSelection` 方法）
- 全程不注入任何键鼠事件，不激活窗口，不改变前台窗口归属

脚本：`tools/Test-LpUiResults.ps1`。

## 4. 冷启动与首查

- UI 启动后第一次查询要付出索引页的首次触摸成本：Debug 构建实测 126.6 ms，Release 构建 8.695 ms。
- 之后同一查询稳定在 1–2 ms（服务端口径），与 §10.3 的 Release 基准一致。
- 结论：首查延迟是文件页冷启动成本，不是算法问题；不做页预热是为了不把 121 MB 映射页一开始就拉进工作集
  （内存预算优先）。
