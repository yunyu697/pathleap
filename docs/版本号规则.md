# 版本号规则

## 单一来源

版本号只有一个写入手：仓库根目录的 `Directory.Build.props`：

```xml
<PathleapVersion>1.0.4</PathleapVersion>
```

其余全部由它派生，不允许在别处手写版本字符串：

| 使用方 | 取值方式 |
| --- | --- |
| 程序集 `Version` / `AssemblyInformationalVersion` | MSBuild 由 `PathleapVersion` 赋值 |
| `AssemblyVersion` / `FileVersion` | 自动去掉 `-alphaN` 后缀得到 `1.0.4` |
| 程序内「关于」/ 窗口底栏 / 托盘状态 / 日志 / IPC 状态 / 基准报告 | `Branding.Version`（运行时读 EntryAssembly 的 InformationalVersion） |
| 打包 zip 名 | 本地 `tools/Package-Lp.ps1` 读 UI exe 的 `ProductVersion`，得到 `Pathleap-<版本>-win-x64.zip` |
| 安装包名 | 本地 `tools/Package-LpInstaller.ps1` 读同一个 `ProductVersion`，得到 `Pathleap-<版本>-win-x64-setup.exe` |
| CI 编译注入 | `build.yml` 从 tag 或 `Directory.Build.props` 解析版本，仅用于编译；不产出任何产物 |
| 更新检查（1.0.4 起） | 客户端读 `Branding.Version`，与清单 `version` 做语义化比较（含预发布优先级） |

## 格式与取值范围

```
<major>.<minor>.<patch>[-alpha<N>]
```

- `major`：不设上限。
- `minor`、`patch`：**0–10**，不允许出现 11。
- `alpha<N>`：预发布编号，不设上限（alpha1、alpha2、…）。
- 起始版本 `1.0.0`；第一次对外推送使用 `1.0.0-alpha1`。

## 进位规则

某一位加 1 后超过 10，就向前进位并把它及其低位归零：

| 操作 | 结果 |
| --- | --- |
| patch + 1，且结果 ≤ 10 | `major.minor.(patch+1)` |
| patch = 10，再升 patch | `major.(minor+1).0` |
| minor = 10，再升 minor | `(major+1).0.0` |
| minor 与 patch 同时为 10，再进位 | `(major+1).0.0` |
| alpha + 1 | 数字位不变，`alpha(N+1)`（`alpha` 编号不受 10 限制） |

示例：

| 当前 | 升 patch | 升 minor | 升 major |
| --- | --- | --- | --- |
| 1.0.0-alpha1 | 1.0.0-alpha2（alpha 升号） | 1.1.0-alpha1 | 2.0.0-alpha1 |
| 1.0.9 | 1.0.10 | 1.1.0 | 2.0.0 |
| 1.0.10 | **1.1.0** | 1.1.0 | 2.0.0 |
| 1.10.3 | 1.10.4 | **2.0.0** | 2.0.0 |
| 1.10.10 | **2.0.0** | 2.0.0 | 2.0.0 |
| 2.0.0 | 2.0.1 | 2.1.0 | 3.0.0 |

（alpha 升号不会把 1.0.0-alpha1 变成 1.0.1，只有显式升 patch 才会。）

## 工具

```powershell
# 预览（不写文件）
pwsh -File .\tools\Next-LpVersion.ps1 -LpBump alpha

# 写回 Directory.Build.props（支持 -WhatIf）
pwsh -File .\tools\Next-LpVersion.ps1 -LpBump alpha -LpApply
```

## Git tag 与 CI

- tag 一律带 `v` 前缀：`v1.0.4`。
- `build.yml` 在 tag 触发时校验 tag 必须以 `v` 开头、去掉前缀后必须是合法版本号，然后以
  `-p:PathleapVersion=<版本>` 注入编译，并打包 zip 与安装包、发布到该 tag 的 Release
  （四项资产：`Pathleap-<版本>-win-x64.zip`、`Pathleap-<版本>-win-x64-setup.exe`、`latest.json`、`latest.json.sig`）。
- 非 tag 构建（main / PR）使用 `Directory.Build.props` 里的版本，不覆盖，只做校验与编译，不产出产物。
- 本机也可用 `Package-Lp*.ps1` 生成等价产物作为备用路径（例如
  `Pathleap-1.0.4-win-x64.zip`、`Pathleap-1.0.4-win-x64-setup.exe`）。
- 版本号与 tag 不一致时，以 tag 为准做编译校验，但本地仓库也应在打 tag 前把 `Directory.Build.props`
  改成同一个值（用 `Next-LpVersion.ps1 -LpApply`），否则下一次 main 构建会回退到旧版本号。
- 已推送的 tag 不重打、不改写；修正版本内容请发新 tag。
