# Pathleap 1.1.2 发布说明

发布日期：2026-11-14
版本：`1.1.2`（上一正式版 `1.1.1`）
tag：`v1.1.2`

版本号按 [版本号规则](版本号规则.md) 进位：`1.1.1` 升一个 patch 即 `1.1.2`（`minor`/`patch` 上限为 10，未越界）。

本版把「未接入」清单里最后两项接回真实功能：下载镜像（A10）与预览版通道（A9）。
设置页与 README 中的「未接入」标签现为 0 处。逐项证据见 [功能状态清单](功能状态清单.md) §1.4、§8.1、§9。

## 1. 下载镜像（A10）

- `ReleaseFeed.ExpandSources` 为同一地址生成源列表：`gh-proxy.com` → `ghfast.top` → GitHub 官方，
  清单与安装包都逐源尝试；
- 每个源下载完成后都做 SHA256 与大小校验，校验不通过或请求失败会自动换下一个源，全部失败才报错；
- 设置页环境变量 `PATHLEAP_UPDATE_MIRROR` 可关闭镜像（`off`）或换成自定义前缀，便于诊断；
- 更新页与设置页文案同步说明「加速镜像优先，失败自动回退官方直链」。

实测 6/6：默认镜像下载清单与安装包成功；强制 `PATHLEAP_UPDATE_MIRROR=https://127.0.0.1:9/`
后清单与安装包都回退官方并成功；失败源有 WARN 日志。

与设计稿的差异：设计稿写「自动选择延迟最低的镜像」，当前实现是固定顺序 + 失败回退，
没有做延迟探测，清单里已如实注明。

## 2. 预览版通道（A9）

- 设置页「更新通道」由静态状态行改为真实开关，写 `AppConfig.UpdateChannel`；
- 预览通道不复用稳定版清单地址，而是读 GitHub API `releases?per_page=30`，
  取发布时间最新、`prerelease=true` 且含 `latest.json` 资产的 Release，再下载它的清单；
- 清单里的 `channel` 必须与所选通道一致，不一致直接中止，**不会悄悄回落到稳定版**；
- 没有预发布时明确提示「预览通道暂无预发布版本；切回稳定版可继续检查正式版。」；
- `api.github.com` 的 TLS 握手在部分网络下不稳定，查询失败最多重试 3 次；
- CI 按版本号解析通道（`-alphaN` 为 preview），`ReleaseTool create --channel` 写入清单，
  预发布 Release 追加 `--prerelease`，不影响 `/releases/latest`。

实测：

- UIA 12/12：开关写 `config.json`、状态文案切换、重启后保持、无预发布时明确提示且不回落、
  关闭后恢复稳定通道文案；稳定通道回归仍为「已是最新」；
- 端到端 8/8：tag `v1.1.2-alpha1`（CI run `43587080361`）发布为预发布 Release；
  1.1.1 客户端切到预览通道后检查到 `1.1.2-alpha1`、验签通过、判定有更新；
  「仅下载」走镜像下载，落地文件 SHA256 与清单一致；同轮稳定通道仍读到 `1.1.1`。

## 3. 更新窗通道标签

更新窗此前直接把配置值当文案（显示 `preview`），与设置页/关于页不一致；
现统一为「预览通道 / 稳定通道」。

## 4. 验证与取证

- 设置页「常规」「关于」两页补拍截图：[79-settings-general.png](shots/79-settings-general.png)、
  [80-settings-about.png](shots/80-settings-about.png)。此前锁屏会话下的误拍已删除，不用锁屏画面充数。
- 构建含 `lp` 前缀变量命名检查；禁用词扫描（`git grep -in listary`）无输出。

## 5. 未验证项（如实列出）

1. **提权开关的界面点击链路未跑**：点击会触发 UAC 并重启进程，需要人在桌面旁确认，本轮未执行；
   后台计划任务链路此前已实测。开关本身已具备 UIA `Toggle` 模式，可随时补测。
2. **真实 SMB/NAS 共享未验证**：网络位置仍用本地临时目录走通端到端；本机没有映射网络驱动器。
3. **浏览器索引未覆盖 Firefox**（不支持），也未在全新浏览器配置上验证。
4. **鼠标唤醒用注入按键验证**：没有物理按下中键/侧键；「不拦截」由代码保证（始终 `CallNextHookEx`）。
5. **提权运行时拖放未实拍**：受 UIPI 限制，普通权限资源管理器不能向管理员窗口拖放，界面与 README 已标注。
6. **预览通道的正式版回退场景**：已用 1.1.2 客户端在预览通道复测，远端为 `1.1.2-alpha1` 时
   判定 `update=False`、界面显示「已是最新版本（1.1.2）」；未在真实升级安装后的 1.1.2 上重复该检查。

## 6. 已知限制

- 镜像为固定顺序 + 失败回退，不做延迟测速（与设计稿有差异，见 §1）；
- 预览通道目前只有 `v1.1.2-alpha1` 一个预发布；正式版发布后，预览通道仍会读到它，
  版本号低于正式版，因此不会触发升级提示；
- `v1.1.2-alpha1` 会长期保留在 Releases 里作为预览通道样例，不需要可在 GitHub 手动删除；
- 附加索引（网络位置 / 索引目录）仍是快照式，不做实时监听；
- 浏览器索引在服务进程内懒加载一次，新记录需重启服务才可见；
- 开机启动只写当前用户 `HKCU`；关于页索引状态依赖后台服务连接。

## 7. 影响范围与升级

- 配置无新增必填字段；`updateChannel` 默认 `stable`，旧 `config.json` 可直接使用；
- 默认开启镜像，但顺序回退官方，网络不通时行为与 1.1.1 一致（只是多两次失败重试）；
- 更新窗通道文案由 `stable`/`preview` 变为中文，仅显示层变化；
- 其余功能与 1.1.1 相同。

## 8. 发布

产物与 1.1.1 同规则：便携 zip + Windows 安装包，版本号来自 `Directory.Build.props` 的
`PathleapVersion=1.1.2`；tag 触发 CI 构建、签名与 Release 上传，发布后用 `ReleaseTool verify`
核对验签与资产。
